# 愿望清单

数据在仓库根目录的 `wishlist.yaml`，图片放在 `docs/home/wishlist/`。推送到 `main` 后，
工作流会自动重新生成网页（子页面 `docs/home/wishlist.html`，主页报头右上角和左侧目录底部有入口）并在 Discord 发一条带大图的通知。
这是现在的 account（test2）的愿望清单；test1 的在 `archive/test1/wishlist.yaml`，不动。还空着时是 `wishlist: []`，加第一件时换成列表。

## 加一件

1. **找准是什么**：从截图 / 链接里读出名字、价格、规格（容量、尺寸、颜色……）、在哪里卖。
   - 货币要有依据（繁体字 + 「毫升」+ 星巴克 → 多半是台湾 NT$）；拿不准就在 `note` 里写明是推断。
   - 可以在 `inbox/*.json` 里搜一下，收集到的消息里常常有原文链接，填进 `url`。
2. **图片**：
   - 用户给了截图：用 Pillow 只裁出商品本身（去掉文字和留白），存成 `docs/home/wishlist/<英文短名>.jpg`，质量 90。
   - 只有网址：下载商品图同样存进 `docs/home/wishlist/`（别直接引用外站图，可能防盗链或失效）。
   - 裁完用 Read 看一眼，确认商品完整、没被切掉。
3. **写进 `wishlist.yaml`**（字段说明在文件顶部），`added` 填今天，`status: 想要`。
   和某个关注项有关（如星巴克马克杯）就填 `watch`，版面上会顺带显示那个关注项的最新消息。
4. **写 `likes`（喜好标签）**：从这件东西看出用户喜欢什么，按「标签: [关键词…]」写，主页「我会喜欢？」靠它挑推荐。
   - 同一个东西的几种写法用 `|` 连成一个词，中日英都写上：`"Snoopy|スヌーピー|史努比"`。
   - 别用太短、容易误命中的英文（`cat` 会命中 category，写 `black cat|kitty`）。只看消息标题；5 个字母以内的英文要是完整的词。
   - 短的片假名 / 汉字会出现在别的词里时，用 `-词` 排除：`"リス|松鼠|-リスト|-イギリス"`、`"マグ|-マグロ"`；地名别当关键词（`宮崎` 换成 `宮崎駿`）。
   - 只是基本属性的标签（马克杯、限定款）放进 `basics`：照样加分，但推荐去重时不看它们。
5. 运行 `python scripts/digest.py recommend`，看看推荐合不合理，再截图检查 `docs/home/wishlist.html` 和主页的「我会喜欢？」，然后提交并推送。
   不要自己发 Discord：推送触发的工作流会发（`state/known_wishlist.json` 记录已通知的）。

## 改状态 / 删除

- 买到了：`status: 已入手`；没买到：`status: 没买到`。
- 去不了 / 买不到了但还想要：`status: 已过期`，子页面上放进下面的「过期的愿望」一栏（色调变淡，不计入想要的合计）。
- 还在犹豫买不买：`status: 纠结`，子页面上放进「纠结名单」一栏（不计入想要的合计，单独算合计）。
  放不放进纠结名单由用户自己决定：用户说「放进纠结名单」「我在纠结这个」才改，说「决定要了」就改回 `想要`。
  放进纠结名单时顺便帮用户找类似的好产品：
  - `alternatives`：上网查 2–3 个同类的好东西，每条 `{name, price, why, url}`。`why` 一句话写清和原来那件比好在哪、差在哪；
    价格和规格要有出处，查不到就不写，不要编。
  - `similar`：每天自动搜同类新产品的搜索词（格式同 items.yaml 的 similar），搜到的会列在卡片上并发 Discord。
- 删除：直接从 `wishlist.yaml` 里删掉那一项（图片也可以一起删）。

## 照片加愿望

愿望清单页可以上传照片（「📷 拍照加愿望」），Claude 定时任务按仓库根目录的 `PHOTOS.md` 处理 `inbox/photos/` 里的照片：
认出物品、按上面的「加一件」整理，`status` 用上传时选的（想要 / 纠结），并写上 `photo: <编号>`。
用户说「处理一下照片」时也照 `PHOTOS.md` 做。
