ユーザー：「スクロールするときの流畅度も解決して」「现在还有点一卡一卡的」。測り方は harness/scroll_measure.py（browser.launch・ログインなし・CPU 4 倍遅く）。
**行番号は測っている間に render.py が変わったので、関数と定数の名前で探すこと。**

## 前（今の本番）
動いている部品は 43,235 個（静的な HTML は 22k、JS が倍にしている）。止まっているときは 60fps・長いタスク 0。引っかかりは全部スクロールの間に起きる。
本物のホイールやタッチでは合成側は約 58fps で流れるが、メインスレッドは 6.5〜14fps。そのため、メインスレッドが描くものがずれて跳ぶ：目次の印と進み棒、小元素が出る瞬間、画像のふわっと出る動き、レンガ並べ（masonry）の並べ直し。

## 原因（測った重さの順）
1. **毎 frame ページ全部を描いている（content-visibility が無い）**：Layerize・Paint・CullRect・HitTest・style の計算で、メインスレッドの約 45%（1400）・40%（390）。
   - 版面全体に `content-visibility:auto` をかけると、1400 は 10.6→26.9fps、390 は 18.3→33.4fps。**ただし `section.sec` 全体にかけると、版面の上にはみ出す小元素が切れる**（GTA 6 で確認）。
   - 直し：`.sec>.grid,.picks>.pkbatch{content-visibility:auto;contain-intrinsic-size:auto 1500px}`（版面は render.py の _section のあたりで作る）。測った値：1400 は 10.9→14.7fps、390 は 13.7→23.8fps、長いタスク −71%。
   - さらに、読み込み時に各 grid の本当の高さを JS で `style.containIntrinsicSize='auto '+h+'px'` に入れる。推測値（1500/2400）のままだと、版面へ飛んだときに 1.5〜1.9k px ずれる。
2. **画像 1 枚ごとに IntersectionObserver が 3,400 個**（`.pic img` すべて、ファビコンも含む）：EMB_JS の `late()`。メインスレッドの 19〜26%、frame あたり 11〜17ms。無くすと長いタスクが −35%（1400）・−27%（390）。直し：共有の observer 1 個にして、一度見えたら外す。`img.ico` は見ない。
3. **scroll のたびに目次を書き換える**（NAV_JS：scroll の listener・`update()`・`pick()`・`layout()`・`--prog`）：JS 1.8 秒、そのうち読みと書きが混ざって強制レイアウト 1.3 秒。Paint・Layerize も毎 frame 起こす。無くすと CLS 0.139→0.003、長いタスク −37%（1400）。scroll の JS を全部無くすと −57%（1400）・−48%（390）。直し：
   - `--prog` を `.nav .bar` 自身に置き、`width` ではなく `transform:scaleX()` にする
   - 変わっていなければ書かない
   - 今の版面は、25 版面への IntersectionObserver 1 個で選ぶ（ループの getBoundingClientRect をやめる）
   - `layout()` で線路の高さを固定する（CLS の元）
4. **ResizeObserver が `.pic` 1,777 個と body 全体の MutationObserver を見ている**（FIT_JS）：5〜9%、frame あたり約 6ms。直し：`p._ok` になったら見るのをやめる、または隠れている版面だけ見る。
5. **画像が 1 枚読み込まれるたびに、ページ全体のレンガ並べをやり直す**（FIT_JS の load → `spans()` → `mason()` を 23 grid 全部、`span()` がカードごとに読みと書き）：1400 で 18 回 × 約 57ms、毎回長いタスク。直し：読み込まれた画像の grid だけやり直し、読みを全部先にしてから書く。
6. **AUTH_JS のスマホの scroll の listener**：毎回 scrollHeight を読み querySelector する（1 回 3.5ms、390 で強制 style 506ms）。直し：要素を覚え、rAF でまとめる。
7. **小元素の縁取りに drop-shadow が 10 個連なっている**（`.emb-in`）：外すと 1400 で 10.6→12.8fps。直し：縁取りを画像に焼き込む、または影を 1 つにする。
8. **画像が表示より大きすぎる**：表示 5.4 メガピクセルのために 70 メガピクセルをデコード。`pics/*.webp`（最大 1280px・srcset 無し）を 55〜80px で、`wishlist/*.jpg` を 42px で出している。デコードはメインスレッドの外なので優先は低い。直し：srcset かサムネイル。

**原因ではなかった（測った）**：「更新中」の帯の動き・embdrift・backdrop-filter（無い）・background-attachment:fixed（無い）。`:has(.vt:hover)` と box-shadow ははっきりしない。
