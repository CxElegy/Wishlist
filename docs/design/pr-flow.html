在对话框里怎么说

都是在 Claude 的对话框里直接打字，不用记命令格式，意思对就行
① 想改东西「帮我把 xxx 加进关注清单」

改版面、加功能、加愿望清单都一样。Claude 改完会自己检查、推送、开 PR（④），把 PR 链接和截图给你

看 CI 结果「CI 过了吗？」

CI 失败或有冲突时，Claude 会自己修好再推；你也可以说「盯着这个 PR」，它会自动处理之后的失败和评论

⑤ 合并「合并」

CI 绿了、截图满意就说这一句。也可以自己在 PR 页面点 Merge，效果一样

其它「截图给我看现在的网页」

「开 PR 合进 main」（会话推了但还没开 PR 时）·「把没用的分支删掉」·「这个 PR 先不要了」

你截图里那条黄色横幅是什么

「claude/xxx had recent pushes · Compare & pull request」= 有个会话推送了分支，但 还没开 PR（停在第 ④ 步一半）
怎么处理（推荐）回到那个会话，跟 Claude 说「开 PR 合进 main」；它会先合并 main、处理冲突、检查完再开 PR
也可以自己点点「Compare & pull request」→「Create pull request」→ 没冲突就「Merge」。有冲突时页面会提示，交给 Claude 处理
不想要了直接不管，或删掉那条分支（让 Claude 用「清理分支」工作流删）。横幅过一阵会自己消失

附录 · 规则

一件事 = 一个会话 = 一个 PR
  • 同时开几个会话没问题，各自一条分支
  • 先合的先上线；后合的那个 PR 可能要先「合并 main」
别直接改 main
  • 云端会话本来就推不了 main（只能推自己的分支）
  • 只有机器人的自动更新直接写 main
冲突怎么判断
  • 两边改了同一个文件的同一处 → 冲突
  • inbox/ reports/ state/：以 main 为准
  • docs/index.html：不手改，重新生成
已经设好的
  • 默认分支 = main，网页从 main /docs 发布
  • 合并后自动删分支
  • 「清理分支」工作流：手动删指定分支，main 永远不删
  • CI：每个 PR 自动跑测试，没通过别合并
