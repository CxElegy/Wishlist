附录 · 规则

一件事 = 一个会话 = 一个 PR
  • 同时开几个会话没问题，各自一条分支
  • 先合的先上线；后合的那个 PR 可能要先「合并 main」
别直接改 main
  • 云端会话本来就推不了 main（只能推自己的分支）
  • 只有机器人的自动更新直接写 main
冲突怎么判断
  • 两边改了同一个文件的同一处 → 冲突
  • inbox/ reports/ state/：以 main 为准
  • docs/index.html：不手改，重新生成
已经设好的
  • 默认分支 = main，网页从 main /docs 发布
  • 合并后自动删分支
  • 「清理分支」工作流：手动删指定分支，main 永远不删
